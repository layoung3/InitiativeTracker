## Confirmed integration blockers and prepared correction

Two defects exist in the earlier route-entry-only composite, rather than in PR #6's standalone baseline:

1. With the shared foundation disabled, N9's old Production check accepted another/custom HTTPS listener plus legacy identity for private media. Transport HTTPS alone is insufficient. The adapter makes N9's media policy explicitly require an enabled, trusted shared origin and validated SecureFeature grant in Production, failing closed if shared policy is absent/disabled. Development-only disposable fixtures retain their explicit exception; never enable Development on a deployed hub to bypass authorization.
2. A grant revoked while an upload awaited its stream could still save because N9's continuation checked only legacy identity. A negative-control test reproduced the unexpected successful save. The adapter passes the shared guard's validated request snapshot to N9, then calls the existing shared durable `Validate`, browser/origin and legacy-identity match checks during N9's existing pre-decode/pre-commit ownership callbacks. Fixed 12-hour expiry, revocation generations and identity snapshots remain owned by the shared service. No legacy/player-recovery/display-pairing credential is promoted to secure authority.

The patch preserves owner/DM checks, antiforgery, quotas, generated private storage, SkiaSharp 4.154.0 PNG/JPEG processing and current public projection. Display tickets remain read-only; profile portraits remain owner/DM private; public application logos remain intentionally public. Character reassociation does not transfer old image provenance: existing mismatched media stays quarantined/404, including for DM, pending a separately reviewed resolution policy. Do not expose it to the new owner or silently rewrite provenance. Application name/settings changes still require secure DM authority. A safe trusted-origin authorization link is added to authenticated layouts; UI states that HTTPS and gameplay sign-in alone are insufficient.

The shared task separately owns a **release prerequisite**: automatic graphical rollback must not restore stale secure grants and revive revoked tickets. Its narrow updater correction, disposable regression, independent review and separately approved home-local/root component installation are prerequisites. This task does not edit updater runtime files or replace the graphical update process. The fixture is now repinned to its corrected shared head `12b38a3`: it copies those installer bytes unchanged into disposable storage and combines the shared installer hash with N9's launcher hash, checking every component. No updater file or manifest in the N9 branch is changed. The correction still requires shared-task final review/CI and separate installation approval. Repin again if that head changes; evidence for an earlier pin does not establish acceptance of a later correction.
