## Confirmed integration blockers and prepared correction

Three integration defects were confirmed in earlier composites:

1. With the shared foundation disabled, N9's old Production check accepted another/custom HTTPS listener plus legacy identity for private media. Transport HTTPS alone is insufficient. The adapter makes N9's media policy explicitly require an enabled, trusted shared origin and validated SecureFeature grant in Production, failing closed if shared policy is absent/disabled. Development-only disposable fixtures retain their explicit exception; never enable Development on a deployed hub to bypass authorization.
2. A grant revoked while an upload awaited its stream could still save because N9's continuation checked only legacy identity. A negative-control test reproduced the unexpected successful save. The policy adapter passes the shared guard's validated request snapshot to N9 and revalidates the durable grant during preparation. Fixed 12-hour expiry, revocation generations and identity snapshots remain owned by the shared service. No legacy/player-recovery/display-pairing credential is promoted to secure authority.
3. Independent review found a second timing window after the final `Validate` callback but before the later SQLite commit. Repeating an unsynchronized validation cannot close that window. The revised adapter consumes the real shared `CommitAuthorized` API from `d84d9a1c`, using the same gate as revoke/cancel. Replacement, removal and application settings all use this boundary: either the transaction commits before revocation completes, or completed revocation prevents callback admission. Grant expiry is checked immediately before callback admission; a bounded transaction already admitted before expiry may finish afterward, without extending the grant.

The commit patch stages validated/re-encoded candidate bytes privately before requesting shared admission. Decode, quota/file scans, file writes/flush/rename, notifications and cleanup stay outside the shared gate. No write transaction is held while waiting for admission. Inside the callback, a fresh SQLite transaction checks current active character/profile ownership and the expected image reference before saving and committing. EF command timeout and Microsoft.Data.Sqlite default/busy timeout are each one second. The shared 250 ms limit bounds gate acquisition only; neither it nor database busy timeouts guarantees a hard wall-clock deadline for slow storage/fsync. This is **single-process serialization** for one hub application process, not a distributed/multiple-writer design. Do not run simultaneous application writers against its data.

Rejected mutations do not prune prior or unrelated referenced media. Previous files are deleted only after a successful commit. Candidate cleanup confirms that the candidate is unreferenced in a fresh DB read; an ambiguous post-commit provider failure preserves any referenced candidate and the previous file and returns unavailable, allowing independent maintenance to reclaim later orphans safely. A failed operation is not reported as a successful save.

The patch preserves owner/DM checks, antiforgery, quotas, generated private storage, SkiaSharp 4.154.0 PNG/JPEG processing and current public projection. Display tickets remain read-only; profile portraits remain owner/DM private; public application logos remain intentionally public. Character reassociation does not transfer old image provenance: existing mismatched media stays quarantined/404, including for DM, pending a separately reviewed resolution policy. Do not expose it to the new owner or silently rewrite provenance. Application name/settings changes still require secure DM authority. A safe trusted-origin authorization link is added to authenticated layouts; UI states that HTTPS and gameplay sign-in alone are insufficient.

The shared task separately owns a **release prerequisite**: the corrected automatic graphical rollback must fence restored secure grants before restarting an old application. Its reviewed source is included in the exact shared pin `d84d9a1c`; final shared CI passed. The composite copies those installer bytes unchanged, composes the installer hash with N9's launcher hash and checks every component. No updater runtime file or manifest on the N9 branch changes here. Separately approved home-local/root component installation remains required; an application archive does not install the corrected updater. Repin/revalidate if the shared source changes.
