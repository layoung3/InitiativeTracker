## Gate B: domain, DNS and clock decisions — separate network approval

Owner chooses an owned FQDN, DNS provider/delegation, narrow file-credential API
plugin, ACME account/contact/terms and renewal responsibility. Prefer delegated
`_acme-challenge` control when provider zone permissions are too broad. Do not
purchase a domain, ship shared wildcard keys or assume a provider exists. Real
backend/plugin installation and its dependency/license audit require approval.

Simplest private hub: one FQDN/per-hub key, direct Kestrel 5445, controlled hotspot
or cooperative router resolver. Public inbound ports/A/AAAA are unnecessary.
Managed external Wi-Fi needs router/client DNS cooperation; isolation and phone
DoH/private DNS can defeat local overrides. Document unsupported combinations.
Future customers need separate names, keys, scopes and transfer/support ownership.

Prepare exact selected private addresses and existing resolver integration using
[the DNS guide](certificate-dns-setup.md). Do not start a competing DNS daemon or
change recovery controllers. LAN/hotspot clients get reachable RFC1918/ULA answers;
on the hub only, the same FQDN must resolve exclusively to loopback for physical
proof. These are different scopes. Never advertise loopback to clients. After
separate approval, verify from each relevant scope:

```bash
# Hub physical scope, using the reviewed installed tools/config:
python3 /usr/local/lib/initiativetracker-https/foundation.py physical-preflight \
  --config /etc/initiativetracker-https/settings.json
# LAN-scope preflight is run on the hub BEFORE its loopback-only override:
python3 /usr/local/lib/initiativetracker-https/foundation.py preflight \
  --config /etc/initiativetracker-https/settings.json \
  --address OWNER_SELECTED_ASSIGNED_PRIVATE_ADDRESS
# After the hub-only override, verify LAN answers on actual clients separately.
```

The LAN tool requires selected addresses assigned to its host; do not run it on a
phone/client pretending its address is the hub's. After the hub loopback override,
client `getent ahosts FQDN`/platform DNS checks plus normal HTTPS reachability are
required independently. Reject stale AAAA/multihoming answers. Verify clock/RTC or
approved offline time-restoration on hub and clients; no expiry-check bypass.
Rollback DNS only from its exact pre-change backup and retest legacy recovery.

## Failure and exact rollback decisions

| Failure | Verified response |
|---|---|
| Issuance/API/internet outage | Leave the valid serving certificate and app alone; retry/alert before actual expiry. Export/issue failure is not a reason to restore DB. |
| Bad promotion | Tool restores a valid previous manifest and verifies actual served peer fingerprint; unconfirmed recovery stops the stage. Manual certificate rollback uses `foundation.py rollback --generation APPROVED_ID` dry-run, then separately approved `--apply`. Never restore expired/untrusted material or agent pins. |
| DNS/clock/expiry | Sensitive HTTPS stays closed. Repair correct local resolution/time/certificates via approved maintenance; no warning bypass or HTTP secrets. Legacy gameplay/display/recovery remains at its old origin if network access permits. |
| Failed graphical update | Inspect actual version/health/data before repeating anything. Guarded rollback restores checkpoint data and fences secure grants before restarting old app. If fencing/stop/restore fails, hold and inspect; do not force startup. |
| Post-acceptance app/data downgrade | Owner approves the exact old release, matching stopped-app backup, lost writes/trust changes and maintenance window. Use the checked restore below, not a binary-only trial against migrated data. |
| Startup asset failure | Restore only the exact backed-up desktop files/modes from that stage; preserve later user edits. App rollback cannot restore external launcher/artwork. |

For manual schema-dependent rollback, use the full checked template in
[recovery.md](../setup/recovery.md#schema-dependent-data-restore), with these
**mandatory changes recorded in the reviewed recovery script before execution**:

1. Select the approved 0.1.5 release/checkpoint and expected last migration; verify
   archive hash, SQLite integrity and schema in empty private staging. Stop/verify
   app inactive, preserve failed data/config and never restore twice after a
   successful automatic rollback. Restore DB, `Media`, keys and identities as one
   checkpoint. Current valid browser certificate/issuer state is not rolled back.
2. Before moving staged data into place or starting ANY app, fence staged secure
   approvals using the exact reviewed runtime helper below. Do not source/execute
   the whole updater script. Set both paths and its approved SHA-256 from the
   reviewed component receipt. Unknown hash, unsafe source/path or any failure
   stops recovery with the service stopped.
3. Retain the atomic version-selection step solely for this explicitly approved
   emergency restore; it is not routine deployment. Reconcile the exact compatible
   non-secret app config/drop-in receipt before start; leave resolver/cert changes
   for their own rollback gates. Never start a binary that would re-migrate the
   restored DB unexpectedly. Verify version/health/migration/identity/pairing and
   retained old-origin gameplay; secure access must remain denied until fresh
   physical recovery establishes a new epoch.

```bash
# In the approved stopped-app staging restore, before data selection/app start:
# Replace all placeholders; the recovery script must exit on any failure.
sudo /usr/bin/python3 -I - \
  /ROOT_OWNED_APPROVED_BUNDLE/hub-updater/runtime/initiativetracker-install-update \
  /PRIVATE_RECOVERY_STAGING/var/lib/initiativetracker \
  APPROVED_INSTALLER_SHA256 <<'PY'
import hashlib, os, stat, sys
from pathlib import Path
script, restored, expected = Path(sys.argv[1]), Path(sys.argv[2]), sys.argv[3]
if len(expected) != 64 or any(c not in '0123456789abcdef' for c in expected):
    raise SystemExit('Set the approved installer SHA256 first.')
for path in (script, *script.parents):
    info = path.lstat()
    if stat.S_ISLNK(info.st_mode) or info.st_uid != 0 or info.st_mode & 0o022:
        raise SystemExit('Source must be the reviewed root-controlled bundle.')
raw = script.read_bytes()
if len(raw) > 131072 or hashlib.sha256(raw).hexdigest() != expected:
    raise SystemExit('Installer source hash mismatch.')
text = raw.decode('utf-8')
start, end = '# BEGIN SECURE ROLLBACK FENCE\n', '# END SECURE ROLLBACK FENCE'
if text.count(start) != 1 or text.count(end) != 1:
    raise SystemExit('Unexpected reviewed helper contract.')
fragment = text.split(start)[1].split(end)[0]
sys.argv = [str(script), str(restored)]
exec(compile(fragment, 'approved-rollback-fence', 'exec'), {'__name__': '__main__'})
PY
```

The fence preserves encrypted stale state for diagnosis but prevents its tickets
from authenticating. Do not delete/reseed Data Protection keys, copy secure
cookies, merge media from different checkpoints or merely remove the fence. Fresh
physical recovery creates the new secure epoch after storage/config verification.
Full stale backup restoration without fencing remains capable of reviving
unexpired revoked grants; no external anti-rollback trust anchor exists.
